Autonomy 2 — C3 Exercise

Conditions d’achèvement

Autonomy 2 — C3 Exercise

8 September · autonomy slot, 1h30 · your oral is on 11 September Serves: C3. Everyone gets the same repository and the same bug.

Setup (5 minutes)

git clone https://github.com/EPF-MDE/coding-agents-management-exam-sales-pipeline.git sales-pipeline
cd sales-pipeline
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest          # the suite passes. Note that.

Read BUG-REPORT.md. It is written the way such a report actually arrives: a symptom, from someone who does not know the cause, with no stack trace.

What you must produce

Push a branch fix/<your-name> by the Freeze — 20:00 on 10 September, the same instant your C1/C2 repository freezes. The slot is where this is meant to get done; it is not a wall. On it:

  1. One command that goes red on this bug. A test invocation, a script, a CLI call. You must have run it. It must fail on the original code and pass once fixed. You will run it live in the oral.
  2. The cause, in two or three sentences, with what pointed you at it. In DIAGNOSIS.md at the repository root.
  3. The fix.
  4. A regression test that fails on the original code. Verify that by stashing your fix and watching it go red. If you have not watched it fail, you do not know it tests anything.
  5. One sentence on where the finding belongs: the specification, an instruction document, or the structure of the code. At the bottom of DIAGNOSIS.md.
  6. One line: did this take you more than 1h30? Yes or no, at the bottom of DIAGNOSIS.md. This is not graded, it is not a band criterion, and no answer to it can move you down. It tells me whether the exercise is the right size — which it can only do if it is true.

How to spend 90 minutes

Roughly: 35 minutes getting a red signal, 30 diagnosing, 25 fixing and writing up. That is the shape of the slot, and it is the shape to aim at.

If you are 40 minutes in with no red command, you are in the failure mode this exercise is built to expose. Stop reading code. Go back to building the loop.

If the slot runs out before you are done, you have until the Freeze on the 10th. Say so in DIAGNOSIS.md; it costs you nothing.

Four things worth saying plainly

The test suite passes, and it will keep passing. Passing tests are not evidence that your fix worked. If the only thing you can show me is a green suite, you have not built a loop.

The first fix that looks right is the one to be most suspicious of. Before you commit to a cause, ask what would have to be true if you were wrong, and check that instead.

Keep track of what you rule out. The oral asks "what did it rule out?" — a list of eliminated causes is the strongest possible answer, and reconstructing it afterwards from memory never sounds convincing.

Everyone has the same bug. In the oral you will run your red command live and be asked how you got to it. A diagnosis you did not derive yourself will not survive that — not because it will be caught, but because the question is about the path, and you will not have walked it.

In the oral

"Show me the one command that went red on the sales pipeline bug. What did it rule out?"

You will run the command on your machine, live. Have the repository open and the terminal ready before you sit down.
